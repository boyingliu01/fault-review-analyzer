# 故障聚类分析系统 - 需求对齐文档 V2

## 1. 原始需求回顾

基于MVP版本的实践反馈，用户对故障聚类分析系统提出了更明确的需求：

### 1.1 核心目标
- 使用大模型进行深度故障根因分析
- 实现故障单的智能聚类，发现相似故障模式
- 提供可视化展示，帮助理解聚类结果
- 支持交互式分析，探索故障间关系

### 1.2 MVP版本存在的问题
1. **缺乏可视化**：仅通过表格展示聚类结果，无法直观看出故障间的相似性关系
2. **分析过程不透明**：用户不清楚聚类是如何进行的
3. **无法调整参数**：聚类参数固定，无法根据数据特点优化
4. **重复计算**：每次分析都重新调用向量化API，浪费token

## 2. 细化后的需求

### 2.1 两阶段分析流程

#### 阶段一：数据准备与向量化（一次性）
1. **信息提取**：从API获取故障单的关键信息
2. **向量化**：使用大模型将故障信息转换为向量表示
3. **持久化存储**：将向量保存到向量数据库，避免重复计算

#### 阶段二：聚类分析（可重复）
1. **加载向量**：从向量数据库读取已保存的向量
2. **参数调整**：支持调整聚类算法参数
3. **多次实验**：可以反复尝试不同参数组合
4. **结果可视化**：提供多种图表展示聚类结果

### 2.2 交互式分析需求
1. **相似度查询**：选择某个故障，查看与其最相似的其他故障
2. **聚类解释**：查看聚类的详细解释和特征
3. **参数调优界面**：可视化调整聚类参数并实时查看效果

### 2.3 可视化需求
1. **散点图**：使用降维技术（UMAP/t-SNE）将高维向量投影到2D/3D空间
2. **热力图**：展示故障间的相似度矩阵
3. **树状图**：展示层次聚类的结构
4. **聚类边界**：在散点图上显示聚类边界

## 4. 技术选型需求

### 4.1 聚类算法选型
需要对比分析以下算法：
1. HDBSCAN（当前使用）
2. K-Means
3. DBSCAN
4. 层次聚类（Hierarchical Clustering）
5. 谱聚类（Spectral Clustering）
6. OPTICS

### 4.2 相似度计算方法选型
需要对比分析以下方法：
1. 余弦相似度（当前使用）
2. 欧氏距离
3. 曼哈顿距离
4. 杰卡德相似度
5. 皮尔逊相关系数

### 4.3 向量数据库选型
需要对比分析以下数据库：
1. Chroma（轻量级，适合本地）
2. Milvus（企业级，功能丰富）
3. Pinecone（云端托管）
4. Weaviate（支持混合搜索）
5. Qdrant（Rust实现，高性能）

### 4.4 降维可视化选型
需要对比分析以下方法：
1. UMAP（当前推荐）
2. t-SNE
3. PCA
4. 自编码器

## 6. 疑问澄清

### Q1: 向量数据库的选择
**问题**：是否需要分布式向量数据库，还是单机版即可？
**假设**：当前数据量较小（<10万条），使用轻量级本地数据库（Chroma/Qdrant）即可

### Q2: 实时性要求
**问题**：故障单数据更新后，是否需要实时更新向量？
**假设**：可以定期批量更新（如每天一次），不需要实时更新

### Q3: 聚类数量
**问题**：期望的聚类数量是多少？是否需要自动确定？
**假设**：使用HDBSCAN自动确定聚类数量，同时提供参数让用户调整

### Q4: 字段扩展优先级
**问题**：需求、设计、开发、测试、生产信息，哪些优先级最高？
**建议优先级**：
1. 生产信息（故障现象、解决方案）- 最高
2. 开发信息（代码提交、变更）- 高
3. 测试信息（测试用例、缺陷）- 中
4. 需求、设计信息 - 中
