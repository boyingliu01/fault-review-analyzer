## 1. 需求共识

### 1.1 核心需求确认

经过讨论，双方就以下需求达成共识：

✅ **两阶段分析流程**
- 阶段一：数据提取 → LLM深度分析（违规模测+代码变更分析+根因验证）→ 向量化 → 持久化存储（一次性执行）
- 阶段二：加载向量 → 聚类分析 → 可视化 → 根因统计 → 改进措施推荐（可重复执行）

✅ **规范知识库与违规模测**
- 使用PDF格式的公司研发规范作为知识库来源
- 自动检测故障是否违反规范
- 违规类型细分：Java编码规范、C++编码规范、数据库规范、运维规范等
- 违规模测准确率目标：≥90%（人工验证50条样本）

✅ **根因可落地性验证**
- 根因必须满足4条可落地性标准：
  1. 具体性：明确指出问题所在
  2. 可改进性：有明确的改进方向
  3. 可验证性：改进效果可以验证
  4. 可归因性：能追溯到具体环节
- 根因可落地性目标：≥95%（人工审核50条样本）
- 不可落地的根因触发重新分析

✅ **代码变更分析**
- 获取故障单关联的代码提交记录（commit ID列表）
- 解析代码diff内容
- 识别变更的文件和代码模式
- 与违规模测结合，检查代码变更是否违反规范

✅ **多模态向量化**
- 支持文本内容向量化
- 支持图像内容向量化（故障截图等）
- 统一使用2048维向量
- 所有故障单统一使用同一API接口，确保向量维度一致

✅ **向量数据持久化**
- 使用Chroma向量数据库本地存储
- 避免重复调用向量化API，节省token成本
- 支持增量更新（新增故障单）
- 元数据包含违规模测结果、根因、改进措施

✅ **聚类算法可调**
- 支持HDBSCAN（主选）、层次聚类、K-Means
- 支持参数调整：min_cluster_size, metric等
- 支持多次实验对比不同参数效果
- 技术约束已明确：K-Means余弦距离通过L2归一化实现，层次聚类ward连接只支持欧氏距离

✅ **可视化展示**
- 根因分布图（柱状图）
- 违规类型分布图
- 改进措施追踪图
- UMAP 2D散点图（按根因着色）
- 相似度热力图
- 树状图（层次聚类）
- 可选3D可视化

✅ **交互式分析**
- Streamlit交互式界面
- 相似度查询：选择故障查看最相似的N个故障
- 参数调优界面：实时调整聚类参数
- 聚类结果解释：查看聚类特征
- 异步任务处理：使用subprocess调用阶段脚本

### 1.2 API字段获取确认

**当前已获取字段（V4）**:
- 基础信息：task_id, title, description(comments), status, priority, create_time, resolve_time
- 需求信息：requirement（需求描述）

- 构建信息：build_info（构建信息）
- 部署信息：deploy_info（部署信息）
- 附件信息：attachments（附件列表）、media_contents（多模态内容）
- 生产信息：incident_time, symptoms, logs, stack_traces, resolution（需单独调用API）

### 1.3 技术选型共识

| 组件 | 选定方案 | 理由 |
|------|----------|------|
| 违规模测 | **LLM+规则引擎** | LLM检测+规则验证，确保准确性 |
| 根因验证 | **规则引擎** | 4条可落地性标准规则化验证 |
| 代码变更分析 | **API获取+diff解析** | 获取commit ID和diff内容 |
| 多模态向量化 | **Volcano Engine多模态API** | 统一接口，维度一致（2048维） |
| 聚类算法 | **HDBSCAN** | 自动确定聚类数量，适合不规则分布 |
| 相似度计算 | **余弦相似度** | 语义向量标准做法 |
| 向量数据库 | **Chroma** | 零配置，Python原生，适合当前规模 |
| 降维可视化 | **UMAP** | 速度快，保留全局结构 |
| 可视化库 | **Plotly** | 交互式，支持Web |
| Web界面 | **Streamlit** | 快速构建，Python原生 |
| 异步处理 | **subprocess** | 避免asyncio事件循环冲突 |

### 1.4 质量指标测量方案共识

| 指标 | 目标值 | 测试集 | 验证时机 | 未达标处理 |
|------|--------|--------|----------|------------|
| 违规检测准确率 | ≥ 90% | 50条人工标注样本 | T2完成后 | 调优Prompt或规则阈值 |
| 根因可落地性 | ≥ 95% | 50条人工审核样本 | T3完成后 | 调优验证规则或重新分析 |

**测试集标注要求**:
- **违规检测测试集**: 由熟悉规范的业务方标注，包含各类违规类型样本
- **根因可落地性测试集**: 由业务方审核根因和改进措施的可执行性
- **标注格式**: JSON格式，包含原始数据、预期结果、标注人、标注时间

## 2. 设计共识

### 2.1 架构设计确认

✅ **模块化设计**
- StandardKB：规范知识库管理
- ViolationDetector：违规检测器
- RootCauseValidator：根因可落地性验证器
- CodeChangeAnalyzer：代码变更分析器
- LLMAnalyzer：增强版LLM分析器（整合违规模测、代码变更、根因验证）
- EmbeddingGenerator：多模态向量化器
- ChromaManager：向量存储
- ClusterAnalyzer：聚类分析器（多算法，含参数合法性校验）
- RootCauseStats：根因统计分析器
- ImprovementRecommender：改进措施推荐器
- Visualizer：可视化组件（根因分布、违规分布、改进追踪、UMAP）
- StreamlitApp：交互式Web界面（subprocess异步处理）

✅ **数据流设计**
```
故障单ID → API提取 → LLM深度分析（违规模测+代码变更+根因验证）→ 文本构建 → 多模态向量化 → Chroma存储
                                                                                        ↓
改进推荐 ← 根因统计 ← 可视化 ← 降维 ← 聚类分析 ← 从Chroma加载 ←────────────────────────────┘
```

### 2.2 接口设计确认

✅ **核心接口**
- `StandardKB.load_from_pdf/pdf_path)` → 加载规范
- `StandardKB.query_by_category(category)` → 按类别查询
- `ViolationDetector.detect(task_info, standards)` → 违规模测
- `RootCauseValidator.validate(root_cause)` → 根因验证
- `CodeChangeAnalyzer.analyze(task_id)` → 代码变更分析
- `LLMAnalyzer.analyze_task(task_info)` → 增强版LLM分析
- `EmbeddingGenerator.generate_embedding(analysis_result, media_contents)` → 多模态向量化
- `FaultClusteringEngine.phase1_prepare_data(task_ids)` → 阶段一准备数据
- `FaultClusteringEngine.phase2_cluster_analysis(algorithm, **params)` → 阶段二聚类分析
- `RootCauseStats.calculate_statistics(root_causes)` → 根因统计
- `ImprovementRecommender.generate_recommendations(stats)` → 改进推荐
- `FaultClusteringEngine.visualize_clusters(result, plot_type)` → 可视化
- `FaultClusteringEngine.find_similar_faults(task_id, top_k)` → 相似度查询

### 2.3 数据模型确认

✅ **核心数据模型**（Section 5.1为最终规范）
- `TaskInfo`: 包含完整流程信息（需求、设计、实现、测试、运维）+ 代码变更 + 多模态内容
- `CodeChange`: 代码变更（commit_id, diff, files_changed等）
- `MediaContent`: 媒体内容（type, content, filename）
- `LLMAnalysisResult`: 包含violation_detection, root_cause, root_cause_validation, **code_changes**, analysis_text
- `ViolationDetection`: 违规模测结果
- `RootCauseValidation`: 根因验证结果
- `ImprovementMeasure`: 改进措施
- `EmbeddingResult`: 包含task_id, embedding, text, **media_type**, metadata
- `ClusteringResult`: 聚类结果
