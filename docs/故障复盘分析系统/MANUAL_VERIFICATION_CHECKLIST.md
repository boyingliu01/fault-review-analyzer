## 文档说明

本文档提供分阶段的人工验证步骤，用于验证故障复盘分析系统的核心功能准确性和可用性。

**验证阶段划分**:
- **阶段1**: 单个故障单自动分析验证（根因 + 改进措施准确性）
- **阶段2**: 少数故障单根因分析 + 自动聚类验证
- **阶段3**: 大规模故障单批量测试验证

### 目标
验证单个故障单的自动复盘分析功能，重点检查：
1. 根因分析的准确性（是否符合故障实际情况）
2. 改进措施的可落地性
3. 报告生成的完整性

基于文档记录，建议使用以下有代表性的故障单：

| 故障单号 | 特点 | 预期分析重点 |

| `11748712` | 有代码变更 (`isCommitCode=Y`) | 创建唯一索引和主键约束 |
| `11751534` | 常规故障单 | 一般性故障分析验证 |

### A. 常用命令速查

```bash
# 环境检查
fault-analyzer --help
fault-analyzer config list

# 数据获取
fault-analyzer fetch single <task_id>
fault-analyzer fetch batch -t "id1,id2,id3"
fault-analyzer fetch status [task_id]
fault-analyzer fetch list

# 分析
fault-analyzer analyze single <task_id> --llm --output ./output/
fault-analyzer analyze batch --cluster --min-size 2 --output ./output/
fault-analyzer analyze clusters --output ./output/

# 报告
fault-analyzer report generate [task_id] --output ./output/
fault-analyzer report list --output ./output/

# 缓存
fault-analyzer cache list
fault-analyzer cache stats
fault-analyzer cache clear [task_id]

# UI
streamlit run src/ui/streamlit_app.py
```

### C. 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| API连接失败 | Token无效或过期 | 检查.env中的DEVCLOUD_TOKEN |
| LLM分析无输出 | LLM API Key未配置 | 检查.env中的LLM_API_KEY |
| 聚类全为噪声 | min_cluster_size过大 | 减小--min-size参数 |
| Embedding失败 | Embedding服务异常 | 检查网络或更换provider |
| UI无法启动 | Streamlit未安装 | pip install streamlit |
