# 故障聚类分析系统 V2 - 共识文档

## 1. 需求共识

### 1.1 核心需求确认

经过讨论，双方就以下需求达成共识：

✅ **两阶段分析流程**
- 阶段一：数据提取 → 向量化 → 持久化存储（一次性执行）
- 阶段二：加载向量 → 聚类分析 → 可视化（可重复执行）

✅ **向量数据持久化**
- 使用Chroma向量数据库本地存储
- 避免重复调用向量化API，节省token成本
- 支持增量更新（新增故障单）

✅ **聚类算法可调**
- 支持HDBSCAN（主选）、层次聚类、K-Means
- 支持参数调整：min_cluster_size, metric等
- 支持多次实验对比不同参数效果

✅ **可视化展示**
- UMAP 2D散点图（主选）
- 相似度热力图
- 树状图（层次聚类）
- 可选3D可视化

✅ **交互式分析**
- 相似度查询：选择故障查看最相似的N个故障
- 参数调优界面：实时调整聚类参数
- 聚类结果解释：查看聚类特征

### 1.2 API字段获取确认

**当前已获取字段：**
- 基础信息：task_id, title, description(comments), status, priority, create_time, resolve_time
- 代码提交：commit_id, message, author, time, changes（需单独调用API）
- 生产信息：incident_time, symptoms, logs, stack_traces, resolution（需单独调用API）

**建议扩展字段（优先级排序）：**
1. 🔴 高优先级：生产信息（故障现象、解决方案、时间线）
2. 🟡 中优先级：开发信息（代码提交、变更记录）
3. 🟢 低优先级：测试信息（测试用例、缺陷记录）
4. ⚪ 可选：需求、设计信息

### 1.3 技术选型共识

| 组件 | 选定方案 | 理由 |
|------|----------|------|
| 聚类算法 | **HDBSCAN** | 自动确定聚类数量，适合不规则分布 |
| 相似度计算 | **余弦相似度** | 语义向量标准做法 |
| 向量数据库 | **Chroma** | 零配置，Python原生，适合当前规模 |
| 降维可视化 | **UMAP** | 速度快，保留全局结构 |
| 可视化库 | **Plotly** | 交互式，支持Web |
| Web界面 | **Streamlit** | 快速构建，Python原生 |

## 2. 设计共识

### 2.1 架构设计确认

✅ **模块化设计**
- DataExtractor：API数据提取
- EmbeddingGenerator：向量化
- ChromaManager：向量存储
- ClusterAnalyzer：聚类分析（多算法）
- UMAPVisualizer：降维可视化
- SimilarityCalculator：相似度计算
- Streamlit UI：交互界面

✅ **数据流设计**
```
故障单ID → API提取 → LLM分析 → 文本构建 → 向量化 → Chroma存储
                                                             ↓
报告生成 ← 可视化 ← 降维 ← 聚类分析 ← 从Chroma加载 ←──────┘
```

### 2.2 接口设计确认

✅ **核心接口**
- `FaultClusteringEngine.phase1_prepare_data(task_ids)` → 准备数据
- `FaultClusteringEngine.phase2_cluster_analysis(algorithm, **params)` → 聚类分析
- `FaultClusteringEngine.visualize_clusters(result, plot_type)` → 可视化
- `FaultClusteringEngine.find_similar_faults(task_id, top_k)` → 相似度查询

**P2 - 可选功能（锦上添花）**

10. 聚类结果解释

12. 数据导出功能
