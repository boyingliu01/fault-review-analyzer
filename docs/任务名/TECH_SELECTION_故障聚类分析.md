# 故障聚类分析系统 - 技术选型报告

## 1. 聚类算法选型

### 1.1 算法对比表

| 算法 | 原理 | 优点 | 缺点 | 适用场景 | 推荐度 |
|------|------|------|------|----------|--------|
| **HDBSCAN** | 层次密度聚类，基于密度可达性 | 自动确定聚类数量；能识别噪声点；对异常值鲁棒；适合不规则形状 | 计算复杂度较高；参数敏感 | 故障聚类（当前使用） | ⭐⭐⭐⭐⭐ |
| **K-Means** | 基于距离的划分，最小化簇内方差 | 简单高效；可扩展性好；结果可解释 | 需预先指定K值；对初始值敏感；假设球形簇 | 已知聚类数量时 | ⭐⭐⭐ |
| **DBSCAN** | 密度聚类，基于邻域密度 | 自动识别噪声；发现任意形状簇；无需指定簇数 | 参数敏感（eps, min_samples）；密度不均时效果差 | 噪声较多时 | ⭐⭐⭐⭐ |
| **层次聚类** | 自底向上或自顶向下合并/分裂 | 无需指定簇数；可生成树状图；结果可解释 | 计算复杂度高；合并后无法撤销 | 需要层次结构时 | ⭐⭐⭐⭐ |
| **谱聚类** | 基于图拉普拉斯矩阵的特征分解 | 处理非凸形状；适合图数据 | 计算复杂度高；需指定簇数 | 图结构数据 | ⭐⭐⭐ |
| **OPTICS** | 密度聚类的扩展，生成可达性图 | 处理密度不均；无需全局密度参数 | 结果解释较复杂；计算量大 | 密度差异大时 | ⭐⭐⭐ |
| **BIRCH** | 平衡迭代归约聚类，使用CF树 | 适合大规模数据；单次扫描 | 对异常值敏感；假设球形簇 | 大规模数据流 | ⭐⭐ |

### 1.2 推荐方案

**主选：HDBSCAN（继续沿用）**
- 理由：
  1. 故障数据通常具有不规则分布，HDBSCAN能发现任意形状的簇
  2. 不需要预先指定聚类数量，适合探索性分析
  3. 能自动识别噪声点（孤立故障）
  4. 对异常值鲁棒，适合故障数据

**备选：层次聚类（Agglomerative Clustering）**
- 理由：
  1. 可生成树状图（Dendrogram），便于理解聚类层次
  2. 当HDBSCAN无法聚类时（数据量太小）作为 fallback
  3. 支持多种连接方式（ward, complete, average, single）

**实验性：K-Means（用户指定K值时使用）**
- 理由：
  1. 当用户明确知道期望的聚类数量时
  2. 计算速度快，适合大规模数据

### 1.3 关键参数说明

**HDBSCAN参数：**
- `min_cluster_size`: 最小聚类大小，小于此数量的点视为噪声
- `min_samples`: 核心点邻域最小样本数，影响密度阈值
- `metric`: 距离度量方式（cosine, euclidean等）

**层次聚类参数：**
- `n_clusters`: 聚类数量
- `linkage`: 连接方式（ward, complete, average, single）
- `metric`: 距离度量

## 2. 相似度计算方法选型

### 2.1 方法对比表

| 方法 | 公式/原理 | 优点 | 缺点 | 适用场景 | 推荐度 |
|------|----------|------|------|----------|--------|
| **余弦相似度** | cos(θ) = (A·B) / (\|A\| \|B\|) | 忽略向量长度，关注方向；适合文本/语义向量 | 不考虑向量大小 | 语义相似度 | ⭐⭐⭐⭐⭐ |
| **欧氏距离** | √(Σ(ai-bi)²) | 直观易懂；几何意义明确 | 受维度灾难影响；对尺度敏感 | 低维数据 | ⭐⭐⭐⭐ |
| **曼哈顿距离** | Σ\|ai-bi\| | 对异常值鲁棒；适合网格数据 | 高维时区分度下降 | 高维稀疏数据 | ⭐⭐⭐ |
| **杰卡德相似度** | \|A∩B\| / \|A∪B\| | 适合集合数据；直观 | 不适合连续向量 | 集合比较 | ⭐⭐ |
| **皮尔逊相关系数** | 协方差/标准差乘积 | 衡量线性关系；标准化处理 | 只捕捉线性关系 | 特征相关性 | ⭐⭐⭐ |
| **马氏距离** | √((x-μ)ᵀΣ⁻¹(x-μ)) | 考虑特征相关性；尺度无关 | 需计算协方差矩阵 | 相关特征数据 | ⭐⭐⭐ |
| **闵可夫斯基距离** | (Σ\|ai-bi\|^p)^(1/p) | 通用框架，p=1为曼哈顿，p=2为欧氏 | 参数选择困难 | 通用 | ⭐⭐⭐ |

### 2.2 推荐方案

**主选：余弦相似度（继续沿用）**
- 理由：
  1. 文本/语义向量的标准做法
  2. 关注语义方向而非向量长度
  3. 对向量的归一化处理效果好

**备选：欧氏距离（配合归一化使用）**
- 理由：
  1. 当向量已经归一化时，欧氏距离与余弦相似度等价
  2. 某些聚类算法（如HDBSCAN内部）使用欧氏距离更高效

**实验性：马氏距离**
- 理由：
  1. 如果后续加入多维度特征（时间、优先级等）
  2. 能考虑特征间的相关性

### 2.3 归一化策略

对于余弦相似度，需要先对向量进行L2归一化：
```python
norms = np.linalg.norm(embeddings, axis=1, keepdims=True)
norms = np.where(norms == 0, 1, norms)
normalized_embeddings = embeddings / norms
```

## 3. 向量数据库选型

### 3.1 数据库对比表

| 数据库 | 架构 | 优点 | 缺点 | 适用场景 | 推荐度 |
|--------|------|------|------|----------|--------|
| **Chroma** | 嵌入式/客户端 | 零配置；Python原生；易集成；支持元数据 | 不适合大规模数据；无分布式 | 本地开发；小规模数据(<10万) | ⭐⭐⭐⭐⭐ |
| **Qdrant** | 服务端/嵌入式 | Rust实现高性能；支持过滤；云原生 | 需额外部署 | 中等规模；需要性能 | ⭐⭐⭐⭐ |
| **Milvus/Zilliz** | 分布式服务端 | 企业级；功能丰富；可扩展 | 部署复杂；资源占用大 | 大规模生产环境 | ⭐⭐⭐ |
| **Weaviate** | 服务端 | 支持混合搜索（向量+关键词）；GraphQL接口 | 学习曲线陡峭 | 需要混合搜索 | ⭐⭐⭐ |
| **Pinecone** | 全托管云 | 无需运维；自动扩展；高可用 | 成本高；数据隐私顾虑 | 快速启动；无运维资源 | ⭐⭐⭐ |
| **Faiss** | 库（非数据库） | Facebook开发；极高性能；GPU支持 | 非持久化；需自行管理 | 研究/实验场景 | ⭐⭐⭐ |
| **pgvector** | PostgreSQL扩展 | SQL接口；事务支持；成熟生态 | 性能不如专用向量库 | 已有PostgreSQL环境 | ⭐⭐⭐ |

### 3.2 推荐方案

**主选：Chroma**
- 理由：
  1. 零配置，开箱即用
  2. Python原生，与当前项目技术栈一致
  3. 支持元数据存储（故障ID、时间、优先级等）
  4. 支持持久化到磁盘
  5. 适合当前数据规模（<10万条故障单）

**备选：Qdrant**
- 理由：
  1. 如果未来数据规模增长
  2. 需要更高性能
  3. 支持嵌入式模式（无需单独部署）

**不考虑：**
- Milvus：部署过于复杂，当前不需要分布式
- Pinecone：成本考虑，数据隐私考虑

### 3.3 Chroma使用方案

**存储结构：**
```python
{
    "collection_name": "fault_embeddings",
    "documents": ["故障分析文本"],
    "embeddings": [[0.1, 0.2, ...]],  # 向量
    "metadatas": [{
        "task_id": 12345,
        "title": "故障标题",
        "priority": "high",
        "create_time": "2024-01-01",
        "cluster_id": 0,  # 聚类后可更新
        "root_cause": "代码bug"
    }],
    "ids": ["task_12345"]
}
```

## 4. 降维可视化选型

### 4.1 方法对比表

| 方法 | 原理 | 优点 | 缺点 | 计算复杂度 | 推荐度 |
|------|------|------|------|------------|--------|
| **UMAP** | 流形学习，保持局部和全局结构 | 速度快；保留全局结构；可控制簇间距 | 参数敏感；随机性 | O(n^1.14) | ⭐⭐⭐⭐⭐ |
| **t-SNE** | 概率分布匹配，保持局部结构 | 可视化效果好；揭示局部结构 | 慢；不保留全局结构；随机性 | O(n²) | ⭐⭐⭐⭐ |
| **PCA** | 线性降维，最大化方差 | 确定性；可解释；快速 | 线性假设；可能丢失非线性结构 | O(n·d²) | ⭐⭐⭐ |
| **Isomap** | 测地距离保持 | 保持流形结构 | 对噪声敏感；计算量大 | O(n³) | ⭐⭐ |
| **LLE** | 局部线性嵌入 | 保持局部几何 | 对参数敏感；不适合大样本 | O(k·n²) | ⭐⭐ |
| **自编码器** | 神经网络非线性降维 | 灵活；可学习复杂映射 | 需训练；黑盒 | 高 | ⭐⭐⭐ |

### 4.2 推荐方案

**主选：UMAP**
- 理由：
  1. 速度比t-SNE快得多，适合交互式探索
  2. 保留全局结构，簇间距离有意义
  3. 可控制最小距离，调整簇的紧凑程度
  4. 支持transform新数据点

**备选：t-SNE**
- 理由：
  1. 最终可视化效果更美观
  2. 适合生成报告图表
  3. 局部结构保持更好

**辅助：PCA**
- 理由：
  1. 快速预览数据结构
  2. 作为UMAP/t-SNE的预处理步骤
  3. 可解释性强（主成分分析）

### 4.3 可视化方案

**2D散点图：**
- 使用Plotly或Bokeh实现交互式图表
- 支持缩放、平移、悬停查看详情
- 按聚类ID着色
- 显示故障标题或ID标签

**3D散点图：**
- 使用Plotly 3D scatter
- 可旋转查看不同角度
- 适合高维数据的初步探索

**热力图：**
- 展示故障间的相似度矩阵
- 按聚类排序，显示簇内相似性
- 使用seaborn或plotly实现

**树状图（Dendrogram）：**
- 展示层次聚类结构
- 使用scipy dendrogram
- 支持截断显示

## 5. 技术栈总结

### 5.1 推荐技术组合

| 组件 | 推荐技术 | 备选技术 |
|------|----------|----------|
| 聚类算法 | HDBSCAN | 层次聚类、K-Means |
| 相似度计算 | 余弦相似度 | 欧氏距离（归一化后） |
| 向量数据库 | Chroma | Qdrant |
| 降维可视化 | UMAP | t-SNE、PCA |
| 可视化库 | Plotly | Bokeh、Matplotlib |
| Web界面 | Streamlit | Gradio、Dash |

### 5.2 架构设计要点

1. **两阶段流程**：
   - 阶段一：数据提取 → 向量化 → 存储到Chroma（一次性）
   - 阶段二：从Chroma加载 → 聚类分析 → 可视化（可重复）

2. **模块化设计**：
   - 数据提取模块（API客户端）
   - 向量化模块（Embedding生成器）
   - 存储模块（Chroma管理器）
   - 聚类模块（多算法支持）
   - 可视化模块（多种图表）
   - 交互模块（参数调整、相似度查询）

3. **可扩展性**：
   - 支持多种聚类算法切换
   - 支持多种相似度度量
   - 支持多种可视化方式
   - 向量数据库可替换

## 6. 实施建议

### 6.1 优先级排序

**P0（核心功能）：**
1. 实现Chroma向量数据库存储
2. 分离向量化阶段和聚类分析阶段
3. 实现UMAP 2D散点图可视化
4. 支持HDBSCAN参数调整

**P1（增强功能）：**
1. 实现相似度查询功能
2. 添加热力图可视化
3. 支持层次聚类算法
4. 添加树状图展示

**P2（高级功能）：**
1. 3D可视化
2. 交互式参数调优界面
3. 聚类结果解释
4. 支持更多聚类算法

### 6.2 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Chroma性能瓶颈 | 中 | 监控数据量，适时迁移到Qdrant |
| UMAP随机性 | 低 | 设置随机种子，保证可复现 |
| 高维向量可视化失真 | 中 | 结合多种降维方法，不依赖单一可视化 |
| 聚类参数调优困难 | 中 | 提供自动参数建议，可视化辅助 |
