# 故障复盘分析系统 - 共识文档

## 一、需求确认

### 1.1 核心目标
开发一个**命令行工具**，能够**不依赖预设故障根本原因**，基于故障处理过程的完整信息独立完成故障复盘分析。

### 1.2 核心特性
| 特性 | 描述 |
|-----|------|
| 无预设标签 | 不预先定义故障原因分类，从数据中自动习得 |
| 自动聚类 | 使用算法自动发现相似故障模式 |
| 知识自习得 | 通过LLM自动提取技术标签，形成动态知识库 |
| 规范冲突识别 | 自动识别违反研发规范的缺陷模式 |

---

## 二、技术决策确认

### 2.1 数据来源
- **主要方式**：从研发管理系统API获取
- **缓存机制**：已获取的数据本地缓存，避免重复请求
- **数据范围**：覆盖故障单完整生命周期
  - 需求阶段
  - 设计阶段
  - 开发阶段（代码提交）
  - 测试阶段
  - 生产问题

### 2.2 应用形态
- **命令行工具**（CLI）
- 支持交互式操作和批处理模式

### 2.3 LLM服务
- **用户可配置**
- 支持的模型类型：
  - OpenAI API (GPT-4/GPT-3.5)
  - 国产大模型（通义千问、文心一言等）
  - 其他兼容OpenAI API的服务

### 2.4 Embedding模型
- **用户可配置**
- 支持的模型类型：
  - OpenAI text-embedding
  - BGE/M3E等开源模型
  - CodeBERT（代码专用）

### 2.5 规范文档
- **两者结合**
- 系统内置通用研发规范模板
- 支持用户扩展自定义规范文档

### 2.6 分析粒度
- **两种模式都支持**
  - 单个故障深度分析
  - 批量故障聚类分析

### 2.7 报告格式
- **Markdown格式**
- 便于阅读和版本管理

---

## 三、功能范围确认

### 3.1 报告内容
1. **故障聚类分类**：将相似故障自动归类，展示聚类结果
2. **根因分析**：分析每类故障的深层根本原因
3. **规范冲突识别**：识别故障是否违反研发规范条款
4. **改进建议**：基于分析结果给出预防改进建议

### 3.2 功能边界

| 包含 | 不包含 |
|-----|-------|
| 故障数据API采集与缓存 | 自动修复代码 |
| 自动聚类与标签生成 | 实时监控告警 |
| 根因分析与报告生成 | 与CI/CD流水线集成 |
| 规范冲突识别 | 自动创建工单 |
| 改进建议生成 | 代码自动重构 |

## 五、验收标准

### 5.1 功能验收
- [ ] 能够从API获取故障数据并缓存

- [ ] 能够对批量故障进行聚类分析

- [ ] 命令行界面友好，有清晰的帮助信息
- [ ] 分析过程有进度提示
- [ ] 错误处理完善，有明确的错误提示
- [ ] 生成的报告格式规范、内容清晰

- [ ] API数据缓存有效，避免重复请求

## 六、技术栈确认

- **Python 3.10+**
