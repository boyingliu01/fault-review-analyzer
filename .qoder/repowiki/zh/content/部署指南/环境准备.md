## 简介
本指南面向首次接触“Bug聚类分析”项目的开发者与运维人员，聚焦于环境准备：包括系统要求、Python版本、内存与磁盘空间建议、Git与虚拟环境创建、依赖安装、环境变量与配置文件设置，以及Linux/macOS/Windows的差异化注意事项。文档同时提供常见问题的定位与修复方法，帮助快速搭建可运行的本地或容器化环境。

## 系统要求
- 操作系统
  - 支持 Linux、macOS、Windows（详见各平台差异章节）
- Python 版本
  - 最低要求：Python 3.10+；推荐 3.10 或更高
- 内存
  - 最低：至少 4GB（生产部署建议）
  - 推荐：8GB 或以上（开发与大规模分析场景）
- 磁盘空间
  - 最低：约 10GB 可用空间（含依赖、缓存、向量库与输出）
  - 开发环境建议预留更多空间以容纳模型与数据

## 环境变量与配置项说明
本项目支持两类配置方式：
- 环境变量（优先级最高）
- YAML 配置文件（默认路径 config/config.yaml）

配置加载顺序
- 命令行参数 > 环境变量 > 配置文件 > 默认值

环境变量覆盖机制
- 管理器在运行时将环境变量映射到配置结构体字段，实现动态覆盖

关键配置分组与变量名
- API 配置
  - API_BASE_URL：研发管理系统 API 地址（必填）
  - DEVCLOUD_TOKEN：研发云访问令牌（必填）
  - API_TIMEOUT：请求超时时间（秒）
  - API_RETRY：请求重试次数
- LLM 配置
  - LLM_PROVIDER：LLM 服务提供商（如 openai/qwen/volcengine 等）
  - LLM_MODEL：模型名称
  - LLM_API_KEY：LLM API 密钥
  - LLM_TEMPERATURE：温度参数
  - LLM_MAX_TOKENS：最大生成 Token 数
  - LLM_BASE_URL：LLM 基础 URL（可选）
- Embedding 配置
  - EMBEDDING_PROVIDER：Embedding 服务提供商
  - EMBEDDING_MODEL：模型名称
  - EMBEDDING_API_KEY：Embedding API 密钥
  - EMBEDDING_BASE_URL：Embedding 基础 URL（可选）
  - EMBEDDING_BATCH_SIZE：批量嵌入大小
- 聚类配置
  - CLUSTERING_ALGORITHM：算法（hdbscan/kmeans/dbscan）
  - CLUSTERING_MIN_CLUSTER_SIZE：最小聚类大小
  - CLUSTERING_MIN_SAMPLES：最小样本数
  - CLUSTERING_METRIC：距离度量（cosine/euclidean/manhattan）
- 缓存配置
  - CACHE_ENABLED：是否启用缓存
  - CACHE_TTL：缓存过期时间（秒）
  - CACHE_STORAGE：存储类型（sqlite/file/memory）
  - CACHE_DB_PATH：缓存数据库路径
- 规范配置
  - RULES_BUILTIN_ENABLED：是否启用内置规范
  - RULES_CUSTOM_PATH：自定义规范路径
- 输出配置
  - OUTPUT_FORMAT：输出格式（markdown/html/json）
  - OUTPUT_DIRECTORY：输出目录
- 日志配置
  - LOG_LEVEL：日志级别（DEBUG/INFO/WARNING/ERROR/CRITICAL）
  - LOG_FILE：日志文件路径
- API 服务配置（运行 API 服务时）
  - API_HOST：监听地址
  - API_PORT：监听端口
  - API_VALID_TOKENS：有效的 API Token 列表
  - API_RATE_LIMIT：每分钟请求限制

YAML 配置示例
- 参考 config/config.yaml.example 中的默认结构与取值范围

## 不同操作系统特定配置
- Linux
  - 系统依赖：可能需要安装编译工具链与数学库（如 build-essential、libopenblas-dev、liblapack-dev）
  - 虚拟环境激活：source .venv/bin/activate
  - 端口占用检查：lsof -i :8000
- macOS
  - 系统依赖：可通过 Homebrew 安装 openblas、lapack 等
  - 虚拟环境激活：source .venv/bin/activate
  - 端口占用检查：lsof -i :8000
- Windows
  - 系统依赖：安装 Visual C++ Build Tools；优先使用预编译 wheel 包
  - 虚拟环境激活：.venv\Scripts\activate
  - 端口占用检查：netstat -ano | findstr :8000

## 常见问题排查与解决方案
- Python 版本不兼容
  - 症状：安装依赖时报版本错误
  - 解决：确认 Python 版本为 3.10+；必要时使用 venv 指定版本
- 依赖安装失败
  - 症状：pip install 报错
  - 解决：升级 pip；尝试国内镜像源；清理缓存后重试；单独安装问题包
- 系统依赖缺失
  - 症状：某些包编译失败
  - 解决：按平台安装必要的系统依赖（见上节）
- 环境变量未加载
  - 症状：提示配置缺失
  - 解决：检查 .env 是否存在且格式正确；确保在进程启动前已加载
- 配置验证失败
  - 症状：启动时报配置校验错误
  - 解决：对照必需变量补齐；检查取值范围与枚举值
- API 调用失败
  - 症状：401/404/超时
  - 解决：核对 API_BASE_URL 与 DEVCLOUD_TOKEN；检查网络连通性；调整超时与重试
- LLM 服务问题
  - 症状：认证失败/超时/模型不存在
  - 解决：检查 LLM_* 相关变量；确认模型名称与服务可用性
- 嵌入生成问题
  - 症状：生成失败/速度慢
  - 解决：检查 EMBEDDING_* 配置；调整批处理大小或使用轻量模型
- 聚类结果为空或效果不佳
  - 症状：无聚类或分类不准
  - 解决：调小最小聚类大小与样本数；更换度量或算法；优化嵌入模型
- 性能与内存问题
  - 症状：分析慢/内存不足
  - 解决：启用缓存；减少批处理；流式处理；增加系统内存
- 数据存储问题
  - 症状：ChromaDB/SQLite 初始化或写入失败
  - 解决：确保目录存在且有读写权限；必要时重建数据库
- 日志问题
  - 症状：日志未生成或级别不生效
  - 解决：检查 LOG_LEVEL 与 LOG_FILE；确保 logs 目录存在
- API 服务无法启动
  - 症状：端口被占用或配置错误
  - 解决：更换端口；检查 API_HOST/API_PORT/API_VALID_TOKENS

## 结论
完成上述环境与配置准备后，即可在本机或容器中运行 Bug 聚类分析项目。建议在生产环境中：
- 明确资源配额（CPU/内存/磁盘），并根据数据规模调整
- 使用环境变量集中管理敏感信息
- 开启缓存与合理的日志级别，便于监控与排障
- 定期备份 data/output/logs 目录，保障数据安全
