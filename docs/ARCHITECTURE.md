# 架构文档

## 概述

故障复盘分析工具是一个基于 AI 的故障分析系统，旨在帮助开发团队快速识别和分析软件故障。系统采用模块化架构，结合了自然语言处理、机器学习和数据挖掘技术，提供自动化的故障聚类、根因分析和报告生成功能。

## 模块结构

### 1. 命令行接口 (CLI)

**路径**: `src/cli/`

CLI 提供了与系统交互的主要方式，支持以下命令：

- `fetch`: 获取任务数据
- `analyze`: 分析任务
- `report`: 生成报告
- `cache`: 管理缓存
- `config`: 配置管理

**核心组件**:
- `main.py`: CLI 入口点
- `commands/`: 各命令实现
- `commands/fetch.py`: 数据获取命令
- `commands/analyze.py`: 分析命令
- `commands/report.py`: 报告命令
- `commands/cache.py`: 缓存管理命令
- `commands/config.py`: 配置命令

### 2. API 服务

**路径**: `src/api/`

API 服务提供了 RESTful 接口，允许其他系统或工具通过 HTTP 与故障复盘分析工具交互。

**核心组件**:
- `server.py`: FastAPI 服务器主文件
- `middleware.py`: 认证和速率限制中间件
- `server_models.py`: API 数据模型
- `dependencies.py`: 依赖注入
- `routes/`: 路由实现
  - `health.py`: 健康检查路由
  - `analyze.py`: 分析路由
  - `clusters.py`: 聚类路由
  - `reports.py`: 报告路由
  - `feedback.py`: 反馈路由
- `client.py`: API 客户端（与研发管理系统通信）
- `models.py`: API 客户端模型
- `exceptions.py`: 异常定义

### 3. 分析引擎

**路径**: `src/analyzer/`

分析引擎是系统的核心，负责协调各个分析组件，完成故障复盘分析。

**核心组件**:
- `pipeline.py`: 分析管道，协调整个分析过程
- `llm_provider.py`: LLM 服务提供者抽象
- `labeling/`: 标签生成模块
  - `generator.py`: 标签生成器
  - `models.py`: 标签数据模型
- `reasoning/`: 根因分析模块
  - `generator.py`: 根因分析生成器
  - `models.py`: 根因分析数据模型

### 4. 数据管理

**路径**: `src/preprocessor/`, `src/embedding/`, `src/clustering/`

数据管理模块负责数据的预处理、嵌入生成和聚类分析。

**核心组件**:
- `preprocessor/`: 数据预处理
  - `processor.py`: 数据预处理程序
  - `models.py`: 预处理数据模型
- `embedding/`: 嵌入生成
  - `generator.py`: 嵌入生成器
  - `models.py`: 嵌入数据模型
- `clustering/`: 聚类分析
  - `analyzer.py`: 聚类分析器
  - `models.py`: 聚类数据模型

### 5. 规范检查

**路径**: `src/rules/`

规范检查模块负责检查代码变更是否符合开发规范。

**核心组件**:
- `engine.py`: 规范检查引擎
- `models.py`: 规范检查数据模型
- `categories.py`: 规范类别定义
- `builtin/`: 内置规范
- `custom/`: 自定义规范

### 6. 报告生成

**路径**: `src/report/`

报告生成模块负责生成分析报告。

**核心组件**:
- `generator.py`: 报告生成器
- `models.py`: 报告数据模型
- `templates/`: 报告模板（Jinja2）

### 7. 数据存储

**路径**: `src/cache/`, `src/feedback/`

数据存储模块负责管理系统的数据存储和检索。

**核心组件**:

**核心组件**:

### 10. 工具和辅助函数

## 数据流程

### 分析流程

```
1. 数据获取 → 2. 数据预处理 → 3. 嵌入生成 → 4. 聚类分析 → 5. 标签生成 → 6. 根因分析 → 7. 规范检查 → 8. 报告生成
```

### 详细流程说明

1. **数据获取**: 从研发管理系统获取任务数据，包括任务详情、代码变更等。
2. **数据预处理**: 对原始数据进行清洗、格式化和特征提取。
3. **嵌入生成**: 将文本数据转换为向量表示。
4. **聚类分析**: 使用 HDBSCAN 算法对任务进行聚类。
5. **标签生成**: 使用 LLM 自动为聚类生成标签。
6. **根因分析**: 使用 LLM 和规则引擎分析故障根因。
7. **规范检查**: 检查代码变更是否符合开发规范。
8. **报告生成**: 生成分析报告，支持多种格式（HTML、Markdown、JSON）。

## 核心技术

### 自然语言处理

- **文本嵌入**: Sentence-Transformers、OpenAI Embeddings
- **文本分析**: LangChain、LLM（OpenAI、Qwen）
- **聚类算法**: HDBSCAN

### 数据存储

- **向量存储**: 内存管理（EmbeddingGenerator LRU 缓存）+ 文件持久化
- **缓存**: SQLite
- **文件存储**: 本地文件系统

### 接口和通信

- **API 框架**: FastAPI
- **HTTP 客户端**: httpx
- **认证**: API Token
- **速率限制**: 自定义中间件

### 开发工具

- **测试**: pytest、pytest-playwright
- **代码检查**: Ruff
- **类型检查**: mypy
- **代码格式化**: Ruff
- **预提交钩子**: pre-commit

## 部署架构

### 本地开发

```
开发环境 → 虚拟环境 → 代码运行 → 数据存储 (本地文件)
```

### 生产部署

```
Docker 容器 → Kubernetes 集群 → 负载均衡 → 应用服务 → 数据存储 (云存储)
```

### 数据存储方案

- **向量存储**: 内存管理 + 文件持久化（可扩展至外部向量库）
- **缓存**: Redis 或 Memcached
- **文件存储**: 云存储（如 S3、OSS）

## 扩展性考虑

### 模块扩展性

- **LLM 集成**: 支持多种 LLM 提供商（OpenAI、Qwen、Claude）
- **嵌入模型**: 支持多种嵌入模型（Sentence-Transformers、OpenAI Embeddings）
- **聚类算法**: 支持多种聚类算法（HDBSCAN、K-Means、DBSCAN）
- **规范检查**: 支持自定义规范

### 性能优化

- **异步处理**: 使用 asyncio 处理并发请求
- **缓存机制**: 支持多种缓存后端
- **批处理**: 支持批量分析任务
- **并行计算**: 使用多进程或多线程提高分析速度

### 监控和日志

- **日志管理**: 使用 loguru 进行日志记录
- **性能监控**: 集成 Prometheus 和 Grafana
- **错误跟踪**: 集成 Sentry 或其他错误跟踪系统

## 安全考虑

- **API 认证**: 使用 API Token 认证
- **请求限制**: 实现速率限制
- **输入验证**: 对所有输入进行严格验证
- **数据加密**: 对敏感数据进行加密存储
- **访问控制**: 实现最小权限原则

## 结论

故障复盘分析工具的架构设计遵循了模块化和可扩展性原则，各个功能模块相互独立，易于维护和扩展。系统采用了先进的 AI 技术，结合了自然语言处理、机器学习和数据挖掘技术，为开发团队提供了自动化的故障分析解决方案。
